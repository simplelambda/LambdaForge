# Validate the complete native behavior with small fixtures · procedure

## Native discovery/example

```bash
lf validate experiments/work.yaml
```

Run in the intended project. Uppercase selectors/paths are placeholders, not a Work-name guess.
Inspect installed help first. These commands are metadata/planning; parsing them does not execute science.

Run the packaged tiny Work in a disposable pyproject project, validate its evidence and use native consumers; do not copy live WISDOM state.

## Decision cases

| Situation | Native interpretation / next step |
|---|---|
| CI runs system Python | Mock installer facts locally; never weaken the real system-Python refusal. |
| Optional SDK absent | Core imports still work; protocol tests require declared optional dependencies. |
| Offline pip failure fixture | Make failure independent of ambient installed packages. |
| Imported wheel smoke | Run outside checkout without editable source fallback. |

## Verification and handoff

Observe real native records and failures, not only mocked widget text. No live cluster/scientific workload or automatic installation is a test prerequisite.
Use owned temporary fixtures, not real study/dataset records; record tests actually executed and explicit skips.

If a capability is missing, stale or unsupported, retain evidence and explain the exact blocker.
Do not create a CLI subprocess adapter, a second runner/result store or an application-specific workaround.
